# 数字员工 + VoiceAgent：Docker 部署简版

适用：单台 Linux 服务器，已安装 Docker、Docker Compose 和宿主机 Nginx。
部署内容：数字员工网页、VoiceAgent 语音服务、LiveKit 音频服务，共 3 个容器。

## 1. 放好代码

拉取本次两个仓库，目录保持如下结构：

```text
/opt/digital-employee/                 # 数字员工源码，包含提交 5cd19eb
/opt/VoiceAgent/                       # 语音源码，包含提交 89f8da2
/opt/VoiceAgent/docs/docker-deploy/    # 本说明和全部配套配置
```

VoiceAgent 使用 `feat/chaobao-browser-assistant` 分支，digital-employee 使用 `master` 分支。
将随文档交付的部署包解压到 `/opt/VoiceAgent/docs/`，得到 `docker-deploy/` 目录。
以下命令全部在 `/opt/VoiceAgent/docs/docker-deploy` 执行，使用这里的 `compose.yaml`。
构建机器需要访问 Docker 镜像源、npm、GitHub 和 pub.dev 下载依赖与模型；服务器需能访问百炼和业务后端。

## 2. 填配置

```bash
cd /opt/VoiceAgent/docs/docker-deploy
cp .env.example .env
chmod 600 .env
vi .env
```

主要填写：

| 配置 | 填什么 |
| --- | --- |
| `SERVER_IP` | 用户浏览器能访问的服务器 IP，不能填 `127.0.0.1` 或容器 IP |
| `WEB_ORIGIN` | 网页完整地址，如 `https://employee.example.com` |
| `LIVEKIT_URL` | 音频信令地址，如 `wss://rtc.example.com` |
| `DASHSCOPE_API_KEY` | 百炼 Key，由开发/平台管理员提供 |
| `LIVEKIT_API_SECRET` | 自行生成至少 32 位随机字符串，可用 `openssl rand -hex 32` |
| `YUXI_KEY` | 智能体 Key，由开发/平台管理员提供 |
| 三个 `*_TARGET` | 按实际环境填写业务、驾驶舱、智能体后端地址；保留示例路径 |

`.env` 不提交 Git，也不要把真实 Key 发到群里。LiveKit 两端的 Key/Secret 由同一份配置注入，不用重复填写。

## 3. 配 HTTPS 和端口

把两个域名都解析到 `SERVER_IP`，按实际域名及证书路径修改 `nginx.https.conf.example`，然后复制到宿主机 Nginx 的 `conf.d` 目录。

```bash
sudo cp nginx.https.conf.example /etc/nginx/conf.d/digital-employee.conf
sudo nginx -t
sudo systemctl reload nginx
```

防火墙/安全组向使用者放行：`443/TCP`、`7881/TCP`、`7882/UDP`。
`8088`、`7880` 仅绑定宿主机回环，由 Nginx 转发；语音服务 `3001` 仅容器内部访问。

网页和语音信令都必须使用浏览器信任的 HTTPS/WSS 证书；通过普通 HTTP IP 地址访问，浏览器无法正常启用麦克风。
本方案面向用户能直连上述媒体端口的内网或专网；若跨公网且媒体端口受限，需另配 TURN。

## 4. 启动

```bash
docker compose config --quiet
docker compose up -d --build
docker compose ps
```

首次构建会下载唤醒、VAD、声纹模型，耗时取决于网络。
启动后访问 `.env` 中的 `WEB_ORIGIN`。

## 5. 验收和日常操作

```bash
# 语音服务检查：应返回 ok=true
curl https://employee.example.com/voice-api/api/health

# 模型检查：assets 中 kws、vad、speaker 应全部为 true
curl https://employee.example.com/voice-api/api/config

# 查看日志
docker compose logs -f --tail=100 voice livekit
```

浏览器允许麦克风后，说 **“你好超宝，请介绍一下自己”**；确认弹窗打开、文字逐步显示、数字人出声，“暂停”能同时停止文字和语音。

更新代码或修改 `.env` 后执行：

```bash
docker compose up -d --build --force-recreate
```

常见问题：

| 现象 | 优先检查 |
| --- | --- |
| 麦克风不可用 | HTTPS 证书、浏览器麦克风授权 |
| 语音接口 403 | `WEB_ORIGIN` 是否与浏览器地址完全一致，含协议和端口 |
| SDK/语音资源 404 | 使用本目录 `web.conf.template`，不要套用旧静态资源代理配置 |
| 已连接但没声音 | `SERVER_IP`、`LIVEKIT_URL`、7881/TCP 和 7882/UDP 是否可达 |
| 智能体报 401 | `YUXI_KEY` 与 `YUXI_TARGET` |

临时 Live2D 使用 Haru 官方示例，正式对外发布前替换为已授权的正式形象，或确认示例及 SDK 的授权范围。

参考：[LiveKit 端口说明](https://docs.livekit.io/transport/self-hosting/ports-firewall/)、[LiveKit 服务配置](https://github.com/livekit/livekit/blob/v1.13.10/config-sample.yaml)。
